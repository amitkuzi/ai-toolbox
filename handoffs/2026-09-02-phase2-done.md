### Worked numeric example (`rules/04-tool-ranking.md`)

Used real `views/tools.yaml` records for subtask "rename 200 STL files by
convention" (`type: script`): `python3`, `git`, and `ollama` (as a cold-start
`trial_candidate`). With `profiles/amit.yaml`'s weights, `python3` and `git`
tie exactly at `effective = 4.60` (both verified, free, local, agent-ready,
same seed score, same verification date) — the formula alone can't separate
them because `task_types` is still empty on every migrated tool (a known
Phase 1 gap, not a rules bug). The tie is broken by `purpose`/`domains` fit
(`python3`'s purpose mentions "file generation," `git`'s doesn't) —
`rules/04-tool-ranking.md` documents this as the tie-break of last resort.
`ollama` computes to `4.10` as a `trial_candidate` and would not have won
even if higher, per the cold-start rule.

## Manual trace verification (per the task brief)

Traced "rename 200 STL files by convention" by hand against the rules as
written and the real catalog:

1. **Swarm gate:** one subtask, deterministic, reproducible bit-for-bit → **L1**.
2. **Orchestrator model:** rule 3 says script work → T0–T1. Rule 2 as
   literally written ("orchestrator tier = hardest subtask tier minus one")
   doesn't cleanly define a "minus one" from T0 for a task with no agent
   delegation at all — **this is the one documented soft spot**: for L1
   tasks where no agent is ever dispatched, there's no delegation gap for
   rule 2's "minus one" to bridge, so the practical reading (matching PRD
   §12's own expected outcome) is that the orchestrator runs directly at the
   subtask's own tier, **T0**, rather than one tier below it. Worth an
   explicit carve-out in `rules/02-orchestrator-model.md` if this ambiguity
   causes disagreement in practice — flagging it here rather than silently
   forcing the rule to fit, per the task brief's own instruction.
3. **Category gate:** Q1 "reproducible bit-for-bit?" → yes → **script**.
4. **Tool ranking:** `python3` vs `git` tie at `effective=4.60`, broken by
   purpose fit → **`python3`**. No agent involved anywhere in this chain.

**Result: `python3`, L1, T0, no agent — matches PRD §12 exactly**, modulo the
rule-2 ambiguity noted above (which happened not to change the outcome here,
since T0 is both "the subtask's own tier" and "one below" once the agent
question is set aside — but the ambiguity is real for a future case where an
L1 script subtask's own tier isn't T0).
