**Design note not in the PRD text:** `store project`'s fold sorts each subject's events by
`(date(ts), kind-intent-priority, ts)`, not raw `ts` alone. Daily/weekly curator runs stamp
historical events with a rounded midnight timestamp for the whole day's batch, which can
sort *before* a same-day intraday event (e.g. a UI-added tool the same day's batch later
"removed" — the removal's midnight ts is earlier than the add's 08:xx ts). Folding by literal
ts alone applied the removal first and the add after, resurrecting dead records. The literal
`ts` on every event is still exactly what was recorded (P4 untouched) — only the fold's
internal sort key changed. See the comment above `_fold_sort_key` in `store.py`.

## Judgement calls made during migration (open for review)

1. **`type` for supply-catalog tools** (which only had `category`): mapped by a
   `category → type` table in `migrate_tools.py` (`CATEGORY_TO_TYPE`), with three per-id
   overrides (`anthropic-api`, `gemini-api` → `model`; `firecrawl` → `mcp`, since it ships
   an official MCP server). Everything else in `category: api/gateway/tool/agent-infra/
   agent-framework/coding-agent` defaulted to `type: script`. This is a judgement call, not
   a fact recovered from the source data — worth an Architect pass before it's load-bearing
   for decision 3 (category gate).
2. **`category` for demand-catalog tools** (which only had `type`): `subagent`/`script`/`kb`
   → `category: tool` (catch-all, since the PRD's category enum has no `subagent` or `kb`
   entry), `skill` → `category: skill`, `mcp` → `category: mcp`. Same caveat.
3. **`task_types`** (★ required per schema) has no source data in either legacy catalog —
   every migrated tool has `task_types: []`. This is a real gap, not silently filled in;
   decision 4's ranking will need real task-type tagging before it's useful. Worth a
   dedicated curation pass, maybe in Phase 2 alongside `04-tool-ranking.md`.
4. **`cost: freemium`** (supply catalog only) has no PRD equivalent (`free|included|metered|
   paid`) — mapped to `metered`.
5. **Changelog replay**: a changelog `"added"` action on a `tool` subject is replayed as
   `tool.status` (informational, non-mutating), not a second `tool.added` — almost every one
   duplicates an id `migrate_tools.py` already gave a full `tool.added` from the *current*
   snapshot, and the changelog line only ever carries a bare name. Replaying it as
   `tool.added` would either fail the schema check (no `type`/`category`) or silently
   clobber the real record depending on fold order. The full historical note (including
   dead/junk ids like the old `github-com` bulk-import stubs) is still in the ledger for
   audit (P2) — it just doesn't manufacture a second "current state" for a tool that already
   has one. `source.added` replays kept as real `source.added` since sources don't carry the
   same strict field requirement.
6. **ADR count discrepancy**: `docs/decisions-draft.md` contains D-008 through D-013 — **six**
   findings, not the "7 ADRs" the task brief expected. Recounted directly from the file;
   nothing was dropped in migration.
