# Catalog data schema

Source of truth for every event shape the Catalog Store (`scripts/store.py`) accepts and
every field a projection (`store project`) computes. Based on PRD §6 — read `docs/PRD.md`
§1a first, the four data principles (P1–P4) are binding and this document only describes
their concrete shape.

Nothing in this file is enforced by code comments alone: `scripts/validate.py` checks every
ledger event against the `kind` table below, and CI fails the build if a payload is missing
a ★ field or a view drifts from `store project`'s output.

---

## 1. Event envelope (every ledger, every `kind`)

| Field | Required | Notes |
|---|---|---|
| `event_id` | always | ULID-style, unique, time-sortable — generated by `store.append`, never supplied by a caller |
| `ts` | always | ISO-8601 UTC, e.g. `2026-09-02T10:00:00.000Z` |
| `kind` | always | one of the `kind` values in §2 |
| `subject_id` | always | the tool / source / model / decision / adr / gap id this event is about |
| `actor` | always | `human:<id>` \| `agent:<name>` \| `auto:<check>` \| `system:migration` |
| `via` | always | `route` \| `outcome` \| `daily-run` \| `weekly-run` \| `monthly-audit` \| `ui-manual` \| `migration` |
| `reason` | **required on every event, unconditionally** (D-011) | free text, ≥ 1 line |
| `supersedes` | optional | prior `event_id` this event corrects (used by `score.retract`, `adr.superseded`) |
| `rules_version` | `decision` only | (D-012) `<rules/VERSION contents>+<short git hash of the rules/ tree>`, e.g. `1.0.0+a1b2c3`, computed by `store.py` at append time from `rules/VERSION` and `git rev-parse --short HEAD -- rules/`; falls back to `dev` if either is unavailable |
| `payload` | always | body, shape depends on `kind` — see §2 |

Rules (P4): no line is ever updated or deleted. `tool.revised` carries only the fields that
changed. Current state of any subject = fold of its events by `ts`. `catalog/views/*` is the
fold's *output*; it is never an input to `append` or `query`.

`store.append` maps `kind` to a ledger collection by its prefix:

| `kind` prefix | `catalog/ledger/<collection>.jsonl` |
|---|---|
| `tool.*` | `tools.jsonl` |
| `source.*` | `sources.jsonl` |
| `model.*` | `models.jsonl` |
| `decision`, `score.*` | `scores.jsonl` |
| `adr.*` | `decisions.jsonl` |
| `gap.*` | `gaps.jsonl` |

## 2. Payload shape per `kind`

### `tool.added` / `tool.revised`
Payload = a (partial, for `.revised`) tool record — see §3 for the full field list. `subject_id`
is the tool's slug `id`.

### `tool.status`
Records a review-status change without editing the tool. Payload:
```json
{"review_status": "verified", "verified": "2026-09-02", "note": "re-checked repo activity"}
```
`review_status` ∈ `seed-unverified | verified | stale | dead`. A score drop ≥ 2 points
(PRD §7.5) is recorded as a `tool.status` note event, not an edit.

### `tool.retired`
Payload: `{"note": "..."}`. Projection marks the tool `retired: true` and `review_status: dead`;
the tool disappears from the routable set but its history is kept.

### `source.added` / `source.revised` / `source.retired`
Payload = a source record: `name`, `type` (`registry|github|blog|newsletter|...`), `url`, `focus`,
`cadence`, `value_score` (1–5), `needs_user_action`, `discovered_via`, `notes`.

### `model.added` / `model.revised`
Payload = a model record — see §6.2: `provider`, `model`, `tier` (`T0|T1|T2|T3`),
`input_usd_mtok`, `output_usd_mtok`, `cache_hit_usd_mtok`, `context_k`, `tokens_per_sec`,
`data_residency`, `strengths` (list), `notes`.

### `decision`
One per routed task (PRD §7). `subject_id` is the `decision_id` (`d-YYYYMMDD-NNN`).
Payload carries **every candidate considered**, not just the winner (P2):
```json
{
  "task": "...", "task_type": "file-batch", "profile": "amit",
  "swarm_level": "L1", "swarm_reason": "...",
  "orchestrator_tier": "T0", "orchestrator_model": "local-fast", "tier_reason": "...",
  "subtasks": [{
    "id": "s1", "gate_answer": "Q1 yes", "type": "script",
    "candidates": [{"tool_id": "python3", "effective": 0.91, "my_score_ctx": 9.2, "samples": 14},
                    {"tool_id": "powershell", "effective": 0.74, "my_score_ctx": 7.0, "samples": 3, "estimate": true}],
    "chosen": "python3", "runner_up": "powershell", "reason": "..."
  }]
}
```
`rules_version` is required on this `kind` only.

### `score.seed`
Initial estimate for a tool, usually from migration or the assessor. Payload:
`{"tool_id": "...", "score": 1-10, "task_type": "...?"}`; `reason` carries the rationale.

### `score.outcome`
Payload: `{"tool_id": "...", "result": "success|partial|fail", "rework": bool, "duration_s": n,
"cost_usd": n, "score": 1-10, "task_type": "...?", "escalated_from": "T1?"}`.
`subject_id` = the `decision_id` this outcome closes.

### `score.human`
Same shape as `score.outcome` minus `result`/`duration_s`/`cost_usd` — just `tool_id` and `score`,
weighted 1.5× in the fold. `actor` is `human:<id>`.

### `score.retract`
Payload `{}`. `supersedes` = the `event_id` of the `score.*` event being withdrawn. The retracted
event is never deleted — `store project` excludes it from the fold by checking `supersedes` links.

### `adr.added` / `adr.superseded`
Payload: `{"title": "...", "body": "markdown...", "superseded_by": "adr-id?"}`. `subject_id` is the
ADR id (e.g. `D-008`).

### `gap.opened` / `gap.hit` / `gap.closed`
Payload for `gap.opened`: `{"gap": "one line", "blocked_subtask": "...", "type_needed": "script|mcp|...", "first_seen": "YYYY-MM-DD"}`.
`gap.hit` payload `{}` — increments `hits` on project. `gap.closed` payload `{"tool_id": "..."}`
— the tool that closed it.

## 3. Tool record fields (payload of `tool.added`; shown in `views/tools.yaml`)

★ = required in the payload · ⚙ = computed by `store project`, never written by a caller.

| Field | ★/⚙ | Notes |
|---|---|---|
| `id`, `name` | ★ | slug, string |
| `type` | ★ | `script \| mcp \| skill \| subagent \| model \| schedule \| kb` — **how it is invoked**, drives decision 3. `plugin` is not a type (D-009) — a plugin bundle is multiple entries tagged `tags: [plugin:<name>]`. |
| `category` | ★ | `runtime \| model \| agent-framework \| agent-infra \| coding-agent \| api \| gateway \| mcp \| skill \| tool` — **domain**, shortlist only |
| `purpose` | ★ | one line |
| `abilities`, `pros`, `cons` | | list |
| `domains` | ★ | shortlist tags |
| `task_types` | ★ | task types this tool fits |
| `cost` | ★ | `free \| included \| metered \| paid` (+ `cost_notes`, optional `cost_per_use_usd`) |
| `local_capable`, `agent_ready` | ★ | bool |
| `data_residency` | ★ | `local \| cloud \| hybrid` |
| `autonomy` | ★ | 1–5 |
| `license` | ★ | SPDX (+ `license_notes`) |
| `install`, `auth` | ★ | `auth`: `none \| account \| api-key \| oauth \| local-path` |
| `entrypoint` | | how it is actually invoked |
| `published_score` | | external score + source, ranks the trial queue only |
| `my_score_current` | ⚙ | fold of `score.*` events (EMA + decay + human ×1.5); `estimate: true` while `score_samples < 5` |
| `score_samples`, `score_trend` | ⚙ | int, `up\|flat\|down` |
| `review_status` | ⚙ | from the latest `tool.status` |
| `verified` | ⚙ | date of the latest successful `score.outcome`; stale after 90 days; absent ⇒ *candidate*, not *routable* |
| `last_reviewed` | ⚙ | date of the latest event that touched this tool |
| `history` | ⚙ | list of every `event_id` that touched this tool (P2) |
| `maturity`, `tags`, `homepage`, `repo`, `notes` | | |

## 4. What `store project` computes and where it writes it

| View file | Folded from | Computed fields |
|---|---|---|
| `views/tools.yaml` | `ledger/tools.jsonl` + `ledger/scores.jsonl` | `my_score_current`, `score_samples`, `score_trend`, `review_status`, `verified`, `last_reviewed`, `history` |
| `views/scores-summary.yaml` | `ledger/scores.jsonl` | per `tool_id`: `my_score_current`, `score_samples`, `score_trend`, `estimate`, `last_outcome_ts`, `by_task_type`, `by_actor` |
| `views/sources.yaml` | `ledger/sources.jsonl` | current state per source, folding `.revised`/`.retired` |
| `views/models.yaml` | `ledger/models.jsonl` | current state per model |
| `views/decisions.md` | `ledger/decisions.jsonl` | ADR list with `status: accepted \| superseded` |
| `views/gaps.md` | `ledger/gaps.jsonl` | open/closed gap tables, `hits` counter |

None of this is written back to the ledger (P3/P4). `store project` is a pure fold: same
ledger in ⇒ same views out, on any backend (`--backend files` or `--backend sqlite`).
